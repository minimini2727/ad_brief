# AD BRIEF — 광고업계 데일리 브리핑

국내 광고 매체·신규 기능·대행사·광고주·규제 뉴스를 매일 헤드라인 중심으로 정리하는 GitHub Pages 사이트입니다.

- 사이트: https://minimini2727.github.io/ad_brief/
- 매일 오전 9시 전후(KST) 예약 작업이 `news.json`에 그날 브리핑을 추가합니다.

## 파일 구조

| 파일 | 역할 |
|---|---|
| `index.html` | 화면(목록·상세·달력·아카이브·검색). 데이터는 `news.json`에서 불러옴 |
| `news.json` | 모든 날짜의 뉴스 데이터. **매일 업데이트는 이 파일만 수정** |
| `fonts/` | 페이퍼로지(Paperlogy) 웹폰트 400/600/700/800 |
| `scripts/validate.py` | `news.json` 검증. 푸시 전에 반드시 실행 |

## 데일리 업데이트 규칙 (예약 작업이 따르는 절차)

1. 오늘 날짜(KST, `YYYY-MM-DD`)가 이미 `news.json`의 `days`에 있으면 아무것도 하지 않고 종료합니다.
2. 수집 범위: 직전 브리핑 이후 ~ 오늘 오전까지 나온 국내 광고업계 소식.
   - 1순위: 아이보스 마케팅 뉴스 (`https://www.i-boss.co.kr/ab-2876`) — 당일 `[M월 D일 마케팅 뉴스클리핑]`과 개별 뉴스 글. 목록 페이지가 캐시돼 보이면 최신 글 번호(`ab-2877-NNNNN`)를 1씩 올려 직접 확인합니다.
   - 2순위: 네이버 광고주센터 공지(`ads.naver.com/notice`), 매드타임스·브랜드브리프·디지털인사이트·뉴스핌 등 업계 매체 웹 검색.
   - 대행사 카테고리는 매일 1건 이상 찾도록 노력하되, 없으면 억지로 채우지 않습니다.
3. 이미 이전 날짜에 실린 소식(같은 사건)은 다시 넣지 않습니다.
4. 6~12건을 작성합니다. 수집할 소식이 없는 날(주말·공휴일)은 날짜를 추가하지 않습니다.
5. `python3 scripts/validate.py` 통과 후 `main`에 커밋·푸시합니다. 커밋 메시지: `brief: YYYY-MM-DD (N건)`.

## 항목 스키마

```json
{
  "id": "MMDD-NN",
  "cat": "feature | platform | agency | brand | policy | data",
  "media": ["naver", "kakao", "meta", "google", "commerce", "tiktok", "etc"],
  "hot": true,
  "title": "헤드라인 (사실 그대로, 과장 없이)",
  "lede": "한 문장 요약",
  "points": ["핵심 내용 한 문장씩, 2~4개. 수치·일정·조건은 원문 그대로"],
  "action": ["실무 체크(편집 메모) 1~2개. 대행사 운영자 관점의 구체적 행동"],
  "source": {"name": "매체명 (원출처: …)", "url": "https://…", "date": "YYYY-MM-DD"}
}
```

| cat | 화면 이름 | 예시 |
|---|---|---|
| feature | 매체 신규기능 | 광고 상품·기능 출시, 지면 변경 |
| platform | 매체·플랫폼 동향 | 알고리즘·정책·전략 변화, AI 에이전트 |
| agency | 대행사 | 대행사·렙사 수주, 파트너 선정, 인수, 업계 행사 |
| brand | 광고주·캠페인 | 브랜드 캠페인, 마케팅 사례 |
| policy | 규제·정책 | 정부·기관 규제, 광고 표현 제한 |
| data | 시장·데이터 | 이용자 수, 거래액, 점유율 통계 |

- `hot: true`는 하루 3~4건, 광고 운영에 바로 영향을 주는 소식에만 붙입니다.
- 원문에 없는 수치·날짜를 만들지 않습니다. 불확실하면 `points`에 "원문 확인 필요"라고 적습니다.
- 최상위 `updated`는 `YYYY-MM-DDTHH:MM:SS+09:00` 형식으로 갱신합니다.
